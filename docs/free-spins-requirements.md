# Free Spins: проверка требований и недостающий контракт

Статус: проверена существующая реализация; новое ТЗ пока не реализовано. Ниже перечислены необходимые данные, а не существующие поля или новые согласованные endpoints.

## Расхождения текущей реализации

- /spin отправляет freeSpin=1 и demoSpin=0 при активных фриспинах. В backend-режиме фронт не списывает ставку самостоятельно.
- Текущий остаток уменьшается и дополнительные фриспины прибавляются на клиенте (src/controllers/spinActions.js). По новому ТЗ остаток должен приходить с сервера после каждой операции.
- Документированный FreeSpin в /spin трактуется как награда, а CountFreeSpin из /init — как остаток. Нельзя считать их взаимозаменяемыми без подтверждения бэкенда.
- Стартовое сообщение содержит фиксированные 15 фриспинов и текст множителя. Их нужно заменить данными конкретной серверной серии.
- Нет подтверждённого серверного накопленного итога серии, её статуса и подтверждения финального зачисления.
- В цикле сейчас возможен collectWin после выигрышного фриспина. Комментарий рядом утверждает обратное. Требуется согласовать, является ли WinSum выигрышем спина или серии и когда допустим /pay.
- После завершения возможен автоматический возврат к autoplay; по ТЗ сначала нужен итоговый диалог и его закрытие игроком.
- Остаток сохраняется и восстанавливается. Обработчик добровольного выхода реализован для Double, но не закрывает Free Spins на сервере.
- Неизвестные результаты запросов блокируются. Автоматическая сверка ожидает серверный контракт.

## Что предоставить от бэкенда

1. Примеры реальных ответов /spin и /init: выдача серии, обычный бесплатный спин, дополнительная награда, последний спин, завершённая и выплаченная серия, прерванная серия.
2. Точные поля и типы для идентификатора серии, её статуса, остатка, новой награды, выигрыша текущего спина, множителя, накопленного и окончательного выигрыша, подтверждения зачисления и актуального баланса. Уточнить, включает ли накопленный итог выигрыш запускающего платного спина.
3. Семантика существующих FreeSpin, CountFreeSpin, WinSum, SumPay и PayDate. Пустой PayDate нельзя считать подтверждением зачисления без явного контракта.
4. Порядок выплаты: автоматическое зачисление сервером или /pay; какая карточка идентифицирует итог серии; поведение при повторном /pay. Нельзя совмещать оба способа с двойным зачислением.
5. Способ добровольного завершения: метод, запрос и ответ, аннулирующие остаток и выплачивающие накопленный выигрыш. Можно расширить существующий API — новый URL сам по себе не требуется.
6. Способ проверки результата по requestId и идентификаторам карточки/серии: в обработке, выполнено, отклонено, не выполнялось. Ответ должен позволять безопасно завершить ранее отправленную операцию.
7. Идемпотентность спина, дополнительных наград и финальной выплаты; порядок при одновременном запросе спина и выхода. Серверное поведение, если браузер закрылся без доставки запроса выхода.
8. Список игр с фриспинами и серверные правила каждой игры. Фронт отображает множитель, но не умножает денежный выигрыш.

## Реализация после согласования

- Единая модель серверной Free Spins-сессии для всех поддерживающих игр и строгая проверка ответов.
- Остаток и общий выигрыш напрямую из ответа сервера; без клиентских -1, +награда и ×3.
- Поле «ВЫИГРЫШ» показывает серверный накопленный итог, включая дополнительные спины.
- По подтверждённому завершению и зачислению — остановка autoplay, итоговый диалог с суммой и валютой; продолжение обычной игры после закрытия.
- Добровольный выход закрывает серию по подтверждённому контракту. Технический сбой сохраняет только сведения для сверки неизвестной операции.
- Проверки: награда, отсутствие локального списания, дополнительные спины, нулевые выигрыши, последний спин, повторные ответы, timeout, восстановление, выход во время запроса, выплата ровно один раз.
